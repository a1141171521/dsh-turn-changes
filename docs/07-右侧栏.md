# 07 · 右侧栏（两代 DSH 的机制与适配）

> 本文只讲**右侧栏怎么挂上去**，以及**升级 DSH 之后要做什么**。
> 改动入口：`dynamic/client/50-sidebar.js`（自建外壳）、`dynamic/client/60-native.js`（原生栏适配）。

## 1. 两代机制

| DSH 版本 | 右栏是什么 | 插件怎么接 |
|---|---|---|
| 0.1.2-rc.1（桌面版 0.8.2 内置） | 布局栅格里的第三列，由 `details` 槽决定内容 | 只能**自己占整列**：注册 `details` 槽（single，遮蔽出厂的工具详情面板），列内自建页签外壳 |
| 0.1.5-rc.1+（桌面版 0.9.0-rc1 起） | **原生右侧栏**：壳自带页签条、固定、引导页 | 只提供**页签类型** + **页签体**：`ctx.sidebarRightTabs.register({id, kind, priority:'extension', title, guide})` + keyed 槽 `sidebar.right.pane.tab`（key = `dsh-turn-changes:<id>`）；开合用 `ctx.sidebarRight.openTab(kind)` |

本机实测（0.1.2-rc.1）：客户端服务目录只有 `layout / locale / sessions / slots / theme / timer / uiWorkspace / workspaces`，
**没有** `sidebarRight` / `sidebarRightTabs`；`details` 槽的出厂占用者会同时声明子槽 `conversation.details.tool`
（工具详情面板），被我们遮蔽后那个子槽一起消失 —— 这是自建外壳的唯一代价。

## 2. 这份源码怎么做到两代通用

`60-native.js` 先按自建外壳装，然后：

```js
ctx.inject(['sidebarRightTabs'], (injected) => { … installNative(registry) … })
```

服务一出现就**撤掉自建外壳**（`releaseFallback()`，即 dispose `details` 注册）并注册原生页签类型；
服务消失（宿主降级）时反向切回自建外壳。0.1.2 上这段永不触发，行为与以前完全一致。

**必须等服务、不能等槽声明**：原生栏先声明 `sidebar.right.pane.tab`，随后才 `provide('sidebarRightTabs')`；
按槽声明触发注册会读到 `undefined` 且**永不重试**（静默什么都不注册）。
这条来自 `omdsh-dev/DSH-better-sidebar` 的真机记录（其 AGENTS.md §3 第 10 条）。

**页签体的高度**：原生宿主 `.paneBody` 是「有确定高度的块级滚动容器」，不是 flex 容器。
`nativeBodyFor()` 因此给每个页签体包一层 `.rsb-native-host`（`height:100%` 的列 flex），
否则根盒塌成内容高度、面板贴不到底。

## 3. 顶部按钮

`conversation.session.header.utilities`（list 座位，零替换风险，出厂只有一个「下载会话日志」）。
点击落点由 `openReviewColumn()` 决定：原生栏可用 → `ctx.sidebarRight.openTab('review')`；否则 → 开自建 details 列。

出厂界面原本没有任何入口能打开右栏，所以这个按钮是我们自己加的。

## 4. 升级 DSH 之后的操作清单

1. **确认新宿主**（应能看到原生右栏服务）：
   - 客户端 `Service.listService` 里应出现 `sidebarRight` / `sidebarRightTabs`；
   - 客户端槽树里应出现 `sidebar.right.pane.tab`（含 `sidebar.right.pane.tab.title`）。
2. **重建会话内加载器**（动态插件随进程重启丢失，源码在仓库里）：
   ```
   node -e "import('./tools/loader.mjs').then(m => { console.log(m.HOST); console.error('----'); console.log(m.CLIENT) })"
   ```
   把 `HOST` / `CLIENT` 两段分别交给 `cordis_define` 的 `code.host` / `code.client`，然后 `cordis_run`。
3. 看日志确认走了哪条路：`[rsb] 原生右侧栏已接管 | 1 个页签类型`（原生）或什么都不打（自建外壳）。
4. 想要「重启后依然在」，用静态形态安装：`node install.mjs`（`cordis.patch.yml` 挂载，`lib/` 是 `dynamic/` 的机械产物）。

## 5. 已知取舍

- 自建外壳占 `details` 时，出厂的工具详情面板（`conversation.details.tool`）让位；原生栏代（0.1.5+）不存在这个问题。
- 面板里 `ReviewPanel` 自带的 ✕ 调的是 `layout.closeDetails()`（0.1.2 语义）。原生栏代里它是一个无害的空操作，
  关页签由原生页签芯片负责。
- 列的宽度在 0.1.2 由布局钳在 300–520px（`dsh-client-ui-layout/lib/client.js` 的 `clampWidth`，可拖拽调宽）。
